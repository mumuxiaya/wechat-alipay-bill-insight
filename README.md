# 微信 / 支付宝消费账单统计系统

把微信支付账单和支付宝交易明细整合成**净支出**口径的可视化大屏，并导出带样式的整理表格。

纯静态前端，没有后端、没有数据库、没有网络请求。文件只在浏览器内存里解析，不会上传到任何服务器。

在线使用：<https://mumuxiaya.github.io/wechat-alipay-bill-insight/>

## 特性

- **两种格式自动识别**：微信 `.xlsx` / `.csv`、支付宝 `.csv`（GBK 编码）拖进去即可，不需要改名或手动指定平台。
- **可合并也可单跑**：两个都传 = 合并汇总；只传一个 = 单平台分析，图表和平台筛选会自动适配。
- **可重复导入**：文件数量不限，可一次多选或分批追加。内容完全相同的文件会自动跳过并提示「已经导入过、数据没有变化」；新文件的日期范围覆盖旧文件时自动替换旧文件；顶部「已导入文件」条可以单个移除，也可以一键「清空账单」。
- **退款归并**：把「支出 1000 + 退款 800」还原成「净支出 200」，而不是两笔流水。微信、支付宝两套不同的退款机制分别处理。
- **净支出口径**：`净额 = 原始金额 − 退款金额`，并把转账 / 红包 / 群收款从纯消费里剔除，单独列出。
- **分类可修正**：关键词词典覆盖常用商户，剩下的长尾商户列在「待确认分类」里，点选一次即重算，规则存在本机浏览器，下次同样商户自动命中。
- **导出带样式的 Excel**：7 个 Sheet，含字体、底色、边框、列宽、冻结首行、筛选、金额格式。
- **零安装**：双击 `index.html` 就能用，也可以直接部署到 GitHub Pages。

## 快速开始

### 方式一：直接打开（最简单）

下载仓库，双击 `index.html`。

### 方式二：本地静态服务

```bash
# 任选一种，Python 3 自带第一条
python -m http.server 8787
npx serve .
```

然后访问 <http://127.0.0.1:8787>。

### 方式三：GitHub Pages

本仓库已开启 Pages，直接访问 <https://mumuxiaya.github.io/wechat-alipay-bill-insight/>。
自己 fork 后，在 Settings → Pages 里把 Source 设为 `main` 分支根目录即可。

## 账单怎么导出

| 平台 | 路径 | 得到文件 |
| --- | --- | --- |
| 微信 | 我 → 服务 → 钱包 → 账单 → 常见问题 → 下载账单 → **用于个人对账** | `.xlsx`（解压密码在微信里） |
| 支付宝 | 我的 → 账单 → 右上角「…」→ 开具交易流水证明 → **用于个人对账** | `.csv`（GBK 编码） |

> 支付宝的 csv 是 zip 里的原始文件，不需要转成 UTF-8，本项目会按 GBK 解码。

## 口径说明

| 指标 | 含义 |
| --- | --- |
| 净支出（含往来） | 所有支出记录的净额之和，`Σ(原始金额 − 退款金额)` |
| 纯消费（不含往来） | 净支出里剔除转账往来 / 红包往来 / 群收款 |
| 往来支出 | 转账、红包、群收款的净额 |
| 净收入 | 所有收入记录的净额之和 |
| 退款冲减 | 已匹配到原单的退款总额 |
| 跨年 / 无原单退款 | 找不到可冲减的原单，单列核对，不冲减本期消费 |
| 有效支出笔数 | 净额 > 0 的支出笔数 |

几点约定：

- 支付宝官方「支出」金额已扣退款，微信未扣，两边原始汇总不能直接相加，本工具统一按净额重算。
- 零钱提现、零钱通 / 余额宝存取、订单关闭等资金搬运记为「不计收支」，不参与消费统计。
- 分类上，支付宝沿用平台自带分类；微信没有分类，按商户关键词词典识别，未命中的归入「其他」。

## 导出的 Excel

「下载整理表格」生成的 `2026年消费账单整合.xlsx` 包含：

| Sheet | 内容 |
| --- | --- |
| 总览 | 核心指标、分平台汇总、分月汇总、支出分类汇总、商户 / 往来对象 TOP15、口径说明 |
| 统一明细 | 21 列全量明细（含分类来源、退款类型、关联退款单号），冻结首行 + 自动筛选 |
| 分类汇总 | 月份 × 分类的净额透视，附收入分类汇总 |
| 退款核对 | 每笔退款与原单的匹配结果 |
| 往来明细 | 转账 / 红包 / 群收款，以及带往来对象的收入 |
| 不计收支 | 提现、理财存取、关闭订单等 |
| 待确认分类 | 落入「其他」的商户，带分类下拉可选 |

## 目录结构

```
wechat-alipay-bill-insight/
├─ index.html          页面骨架 + 样式 + 上传引导
├─ assets/
│  ├─ parser.js        文件解析：xlsx / GBK csv → 统一记录，退款归并，关键词分类
│  ├─ core.js          统计口径层：KPI、月度、分类、平台、商户、往来
│  ├─ charts.js        ECharts 图表（6 个，SVG 渲染，点击联动筛选）
│  ├─ excel.js         ExcelJS 导出 7 个 Sheet
│  ├─ app.js           交互层：上传、筛选、抽屉、归类、导出
│  └─ fonts/           Outfit 字体（本地化，避免外链）
└─ vendor/
   ├─ echarts.min.js   ECharts 5（Apache-2.0）
   └─ exceljs.min.js   ExcelJS 4.4.0（MIT）
```

脚本按 `echarts → exceljs → parser → core → charts → excel → app` 顺序加载，全部挂在 `window` 上，没有打包步骤。

## 隐私

- 无任何网络请求，打开浏览器 DevTools 的 Network 面板即可自证。
- 解析结果只存在内存；「商户 → 分类」的修正存在 `localStorage`，可在大屏「待确认分类」里一键清空。
- 导出的 Excel 也只在本地生成。

## 已知限制

- 支持多个账单文件（例如按月 / 按年分批导出）；但同一平台的两个文件若日期范围只部分重叠（既不完全相同、也不互相包含），会按两份数据追加，可能重复计数，请自行避免。
- 跨年份数据可以合并统计，但月份轴按「1 月 … 12 月」显示，两年同月会并到一起；标题也会退化为「消费账单」。
- 跨年退款不冲减当期消费，会单列在「退款核对」。
- 分类是关键词规则，未覆盖的商户会落到「其他」，需要手动点选一次。
- 微信账单若是加密的 zip，需要先在微信里拿到解压密码、解出 xlsx 再上传。
- 需要较新的浏览器（`TextDecoder` 的 GBK 支持），Chrome / Edge / Safari / Firefox 均可。

## 二次开发

想扩充分类词库，改 `assets/parser.js` 里的 `RULES` 即可，格式是 `[分类名, 正则]`，**顺序敏感**——越具体的规则放越前，「其他」是兜底。分类名必须出现在 `CATEGORIES` 里。
